# Synthetic Trace Replication and Annotation

This guide explains how to use `scripts/annotate_and_multiply_traces.py` to generate synthetic trace corpora for benchmarking.

The script duplicates a baseline OTel JSON trace session and injects custom attributes based on configured probability distributions.

---

## Prerequisites & Constraints

> **Important:** The replicator script requires a **local baseline trace JSON file** (`--baseline-file`).
>
> To replicate a Hugging Face dataset, download a raw session trace JSON file from the dataset, save it locally, and pass its path to `--baseline-file`. The script outputs a replicated, annotated corpus of local JSON trace files to `--output-dir`.

---

## CLI Reference

Execute the replicator script to generate your corpus:

```bash
python3 scripts/annotate_and_multiply_traces.py \
  --baseline-file examples/otel/test_traces/simple/simple_chain.json \
  --output-dir /tmp/annotated_traces \
  --num-sessions 100 \
  --labels-config config.json \
  --clean  # Optional: clears the output directory first
```

### Command Arguments

| CLI Argument | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `--baseline-file` | String | Yes | Path to the local baseline trace JSON file to replicate. |
| `--output-dir` | String | Yes | Destination directory for generated trace files. |
| `--num-sessions` | Integer | Yes | Number of session trace files to produce (minimum 1). |
| `--labels-config` | String | Yes | Path to a JSON config file or inline JSON string defining label distributions. |
| `--clean` | Flag | No | Clears the target `--output-dir` before generating new traces. |

> **Warning:** Do **not** use `--clean` when using the **Heterogeneous Workload Shapes Workaround**, as it will erase session traces generated by previous runs.

## Label Configuration Schema (`--labels-config`)

The replicator supports two configuration modes. The configuration can be loaded from a JSON file or passed directly as an inline JSON string.

### Mode A: `independent` (Uncorrelated Cartesian Mixture)

Use independent mode when attributes are uncorrelated. The script computes the Cartesian product of all attributes and their joint probabilities.

```json
{
  "mode": "independent",
  "labels": {
    "priority": {
      "premium": 0.3,
      "standard": 0.5,
      "best-effort": 0.2
    },
    "tenant_id": {
      "tenant-a": 0.4,
      "tenant-b": 0.6
    }
  }
}
```

*In this configuration, the joint probability `P(premium, tenant-a) = 0.3 * 0.4 = 0.12`. 12% of all generated sessions will be assigned this specific joint attribute pair.*

### Mode B: `joint` (Correlated QoS Profiles)

Use joint mode when attributes are correlated (e.g., mapping specific tenants to specific priority tiers).

```json
{
  "mode": "joint",
  "slices": [
    {
      "labels": {
        "priority": "premium",
        "tenant_id": "tenant-a"
      },
      "weight": 0.3
    },
    {
      "labels": {
        "priority": "best-effort",
        "tenant_id": "tenant-b"
      },
      "weight": 0.7
    }
  ]
}
```

## Key Features

### 1. Weight Normalization

If the sum of the configured weights does not equal `1.0`, the script automatically normalizes them at startup.

### 2. Exact Session Allocation

The script uses the **Hamilton Method (Largest Remainder Method)** to allocate sessions. This ensures the total number of generated session files matches `--num-sessions` exactly, preventing rounding discrepancies.

### 3. DAG Preservation & ID Regeneration

For each replicated session, the script generates a unique `trace_id` and regenerates all `span_id`s while preserving parent-child relationships (DAG structures) and message contents.

### 4. Zero-Allocation Warnings

If `--num-sessions` is too small relative to the configured slices, some slices may receive zero sessions. The script logs a warning listing the affected combinations to `stderr`:

```text
WARNING: --num-sessions (5) is less than the number of configured slices (6). The following slices will receive 0 sessions:
  - priority=best-effort, tenant_id=tenant-b
```

## Advanced Workflows: Heterogeneous Workload Shapes Workaround

By default, all replicated sessions share an identical span structure (DAG shape and message lengths). Only their custom attributes differ.

To simulate heterogeneous workloads (e.g., different tenants running different prompt lengths), run the replicator multiple times with different baseline files targeting the same `--output-dir` without using the `--clean` flag:

1. Generate standard short Q&A sessions for `tenant-a`:

   ```bash
   python3 scripts/annotate_and_multiply_traces.py \
     --baseline-file baselines/short_qa.json \
     --output-dir /tmp/mixed_corpus \
     --num-sessions 50 \
     --labels-config "{\"mode\":\"joint\",\"slices\":[{\"labels\":{\"priority\":\"standard\",\"tenant_id\":\"tenant-a\"},\"weight\":1.0}]}"
   ```

2. Generate premium long agentic sessions for `tenant-b`:

   ```bash
   python3 scripts/annotate_and_multiply_traces.py \
     --baseline-file baselines/agent_chain.json \
     --output-dir /tmp/mixed_corpus \
     --num-sessions 50 \
     --labels-config "{\"mode\":\"joint\",\"slices\":[{\"labels\":{\"priority\":\"premium\",\"tenant_id\":\"tenant-b\"},\"weight\":1.0}]}"
   ```

When `inference-perf` runs, it loads all session files within `/tmp/mixed_corpus` in parallel, driving a heterogeneous workload.

> **Note on Mixture Ratios:** When replaying a heterogeneous corpus, omit `num_sessions` in your YAML stage config to replay the entire directory. Specifying a smaller `num_sessions` will cause random sampling, which can statistically skew the configured mixture ratios.
